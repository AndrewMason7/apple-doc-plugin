## 2. High & Critical Severity Defects

### Defect 1: SQL Operator Precedence Flaw in `findFuzzySuggestions` Leaks Cross-Framework Symbols & Wastes Resources

- **Severity**: **HIGH**
- **Location**: [`src/server/db/database.ts:1227-1243`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/server/db/database.ts#L1227-L1243)
- **Root Cause**:
  In `AppleDocsDB.findFuzzySuggestions`, the SQL candidate selection query constructs its `WHERE` clause as follows:

  ```ts
  let sql = `
      SELECT title, framework, path, kind, is_primary_type
      FROM symbols
      WHERE abs(length(title) - ?) <= ?
         OR is_primary_type = 1
         OR path LIKE '%/' || ? || '%'
  `;
  const params: (string | number)[] = [
  	cleanTargetName.length,
  	maxDist,
  	cleanTargetName.toLowerCase(),
  ];

  if (targetFramework) {
  	sql += ` AND framework = ? COLLATE NOCASE`;
  	params.push(targetFramework);
  }
  ```

  In SQL, `AND` has higher operator precedence than `OR`. The evaluated boolean logic is:

  ```sql
  WHERE abs(length(title) - ?) <= ?
     OR is_primary_type = 1
     OR (path LIKE '%/' || ? || '%' AND framework = ? COLLATE NOCASE)
  ```

- **Observed Impact**:
  1. **Cross-Framework Leakage**: When a user scopes a query to `SwiftUI`, any symbol matching the length distance or having `is_primary_type = 1` from **UIKit, Foundation, AppKit, or CoreLocation** is selected and returned in the suggestions list.
  2. **Severe Query Over-read**: Instead of scanning ~1,500 symbols within the requested framework, SQLite pulls **7,184 rows** into Node.js heap memory, running CPU-heavy Damerau-Levenshtein calculations on all of them.
- **Empirical Reproduction**:
  Running `findFuzzySuggestions('UIVew', 'SwiftUI', 5)` returns:
  ```json
  [
  	{
  		"title": "UIView",
  		"framework": "UIKit",
  		"path": "/documentation/uikit/uiview",
  		"kind": "class",
  		"distance": 1
  	},
  	{
  		"title": "View",
  		"framework": "SwiftUI",
  		"path": "/documentation/swiftui/view",
  		"kind": "protocol",
  		"distance": 2
  	},
  	{
  		"title": "UIKey",
  		"framework": "UIKit",
  		"path": "/documentation/uikit/uikey",
  		"kind": "class",
  		"distance": 2
  	}
  ]
  ```
  Notice that UIKit symbols are returned despite `framework: "SwiftUI"` being explicitly provided.
- **Remediation**:
  Wrap the `OR` clauses in parentheses before appending the `AND framework = ?` constraint:
  ```ts
  let sql = `
      SELECT title, framework, path, kind, is_primary_type
      FROM symbols
      WHERE (abs(length(title) - ?) <= ?
         OR is_primary_type = 1
         OR path LIKE '%/' || ? || '%')
  `;
  ```

### Defect 2: `npm run check` Fails Due to Unignored `.pytest_cache/` Artifacts

- **Severity**: **HIGH (Build / CI Blocker)**

- **Remediation**:
  Add Python test and runtime caches to `.prettierignore` and `.gitignore`:
  ```text
  .pytest_cache/
  __pycache__/
  *.pyc
  .cache-test-*
  ```

### Defect 3: Obsolete Dead Handlers Persist in `dist/` and Are Packaged into Releases

- **Severity**: **HIGH (Packaging & Cleanliness)**
- **Location**: [`package.json:10-24`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/package.json#L10-L24), [`package.json:44`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/package.json#L44), [`dist/server/handlers/`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/dist/server/handlers/)

- **Observed Impact**:
  Because `package.json` specifies `"files": ["dist/", ...]`, any `npm pack` or `npm publish` ships deleted, deprecated code to end users.
- **Remediation**:
  Update `build` to clean `dist` prior to compilation, or add a `prebuild` hook:
  ```json
  "scripts": {
    "clean": "node -e \"fs.rmSync('dist', { recursive: true, force: true })\"",
    "build": "npm run clean && tsc && chmod +x dist/index.js"
  }
  ```

## 3. Medium Severity Flaws & Edge Cases

### Defect 4: DocC AST Formatter Drops `orderedList` (Numbered Steps)

- **Severity**: **MEDIUM**
- **Location**: [`src/apple-client/docc-formatter.ts:72-87`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/apple-client/docc-formatter.ts#L72-L87), [`src/apple-client/types/index.ts:60-61`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/apple-client/types/index.ts#L60-L61)
- **Root Cause**:
  `DocCContentNode` defines both `unorderedList` and `orderedList`. However, `formatContentNodes` in `docc-formatter.ts` only checks for `unorderedList`:
  ```ts
  } else if (node.type === 'unorderedList' && Array.isArray(node.items)) {
      const listItems = node.items
          .map((item) => `- ${formatContentNodes(item.content).trim()}`)
          .filter(Boolean)
          .join('\n');
      if (listItems) {
          parts.push(listItems);
      }
  }
  ```
  `orderedList` is never handled and falls through to empty output.
- **Observed Impact**:
  Numbered lists, sequential procedures, and ordered configuration steps present in official Apple documentation are silently erased from the output.
- **Remediation**:
  Add handling for `orderedList`:
  ```ts
  } else if (node.type === 'orderedList' && Array.isArray(node.items)) {
      const listItems = node.items
          .map((item, idx) => `${idx + 1}. ${formatContentNodes(item.content).trim()}`)
          .filter(Boolean)
          .join('\n');
      if (listItems) {
          parts.push(listItems);
      }
  }
  ```

### Defect 5: Unbounded, Never-Expiring Disk Cache in `FileCache`

- **Severity**: **MEDIUM**
- **Location**: [`src/apple-client/cache/file-cache.ts:40-101`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/apple-client/cache/file-cache.ts#L40-L101)
- **Root Cause**:
  Unlike `MemoryCache` (which implements a 10-minute TTL and 500-item LRU eviction limit), `FileCache` writes JSON files directly to `.cache/<symbol>.json` with **no expiration timestamp, no TTL validation, and no size or entry count ceiling**.
- **Observed Impact**:
  Once a symbol or technology is written to `.cache/`, it is never refreshed from the Apple CDN, even across OS releases. Furthermore, prolonged usage indefinitely consumes local disk storage.
- **Remediation**:
  Introduce a maximum cache age (e.g., 14 or 30 days) by checking file `mtime` or embedding a timestamp envelope `{ timestamp, data }` in `atomicWriteJson`.

### Defect 6: Unhandled Write Errors in `FileCache` Crash Documentation Lookups on Read-Only Environments

- **Severity**: **MEDIUM**
- **Location**: [`src/apple-client/cache/file-cache.ts:31-35`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/apple-client/cache/file-cache.ts#L31-L35), [`src/apple-client.ts:42, 56`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/apple-client.ts#L42)
- **Root Cause**:
  In `FileCache.atomicWriteJson`:
  ```ts
  try {
  	await fs.writeFile(tmpPath, JSON.stringify(data, null, 2), 'utf8');
  	await fs.rename(tmpPath, filePath);
  } catch (err) {
  	await fs.unlink(tmpPath).catch(() => {});
  	logger.warn(`Failed atomic write to ${filePath}:`, err);
  	throw err;
  }
  ```
  `atomicWriteJson` re-throws the filesystem error. In `AppleDevDocsClient.getSymbol` and `getFramework`:
  ```ts
  const data = await this.httpClient.getDocumentation<SymbolData>(cleanPath);
  await this.fileCache.saveSymbol(cleanPath, data);
  return data;
  ```
- **Observed Impact**:
  If the plugin is installed globally (e.g. `/usr/local/lib/node_modules/apple-doc-plugin`) or executed in a read-only container/sandbox where `.cache` cannot be written, the `saveSymbol` call throws an uncaught exception, failing the entire user query even though the Apple CDN fetch succeeded!
- **Remediation**:
  Make disk cache persistence advisory and non-fatal:
  ```ts
  try {
  	await this.fileCache.saveSymbol(cleanPath, data);
  } catch (cacheErr) {
  	logger.warn('Failed writing to file cache:', cacheErr);
  }
  ```

### Defect 7: Hermes Bridge 15-Second Cold Start Handshake Timeout

- **Severity**: **MEDIUM**
- **Location**: [`hermes_bridge.py:190-196`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/hermes_bridge.py#L190-L196), [`bin/launcher.cjs:12-24`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/bin/launcher.cjs#L12-L24)
- **Root Cause**:
  `bin/launcher.cjs` automatically runs `npm install --omit=dev` and rebuilds native `better-sqlite3` bindings when `node_modules` or compatible binaries are missing. This build step typically takes 20 to 45 seconds on fresh checkouts.
  In `hermes_bridge.py`:
  ```python
  if not event.wait(timeout=15.0):
      with self._lock:
          self._pending_requests.pop(req_id, None)
      err_diagnostics = "\n".join(list(self._stderr_buffer)[-10:])
      raise TimeoutError(
          f"Timed out initializing Apple Doc MCP server. Recent stderr:\n{err_diagnostics}"
      )
  ```
- **Observed Impact**:
  A fresh Hermes agent plugin installation times out and terminates during initial handshake because 15.0 seconds is insufficient for `npm install` and native C++ compilation.
- **Remediation**:
  Increase the initial handshake timeout in `hermes_bridge.py` to 60.0 or 90.0 seconds.

### Defect 9: Exact Symbol Detection Skips Lowercase Swift Methods and Functions

- **Severity**: **MEDIUM**
- **Location**: [`src/server/handlers/search-symbols.ts:29-38, 440-442`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/server/handlers/search-symbols.ts#L29-L38)
- **Root Cause**:
  In `search-symbols.ts`:
  ```ts
  const looksLikeExactSymbol = (query: string): boolean => {
  	if (query.includes('*') || query.includes('?') || query.includes(' ')) {
  		return false;
  	}
  	return (
  		/^[A-Z][a-zA-Z\d]*(?:[./][A-Z][a-zA-Z\d]*)*$/.test(query) ||
  		query.startsWith('documentation/')
  	);
  };
  ```
  And in `tryExactSymbolMatch`:
  ```ts
  if (queryMode !== 'exact-symbol') {
  	return undefined;
  }
  ```
- **Observed Impact**:
  Any query for a Swift method, function, property, or view modifier that begins with a lowercase letter (e.g. `onAppear`, `task`, `body`, `init`) is classified as `queryMode: 'keyword'`. As a result, `tryExactSymbolMatch` is skipped entirely for all lowercase symbols, disabling the exact CDN resolution fallback for functions.
- **Remediation**:
  Expand `looksLikeExactSymbol` to recognize camelCase identifiers:
  ```ts
  /^[a-zA-Z_][a-zA-Z\d_]*(?:[./][a-zA-Z_][a-zA-Z\d_]*)*$/;
  ```

### Defect 12: Platform Filter Bypass for Semantic-Only Search Hits

- **Severity**: **MEDIUM**
- **Location**: [`src/server/services/search/hybrid-search.ts:292`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/server/services/search/hybrid-search.ts#L292), [`src/server/handlers/search-symbols.ts:233`](file:///Users/andrew/Documents/GitHub/apple-doc-plugin/src/server/handlers/search-symbols.ts#L233)
- **Root Cause**:
  When a semantic match is not found in the initial FTS search, `HybridSearchEngine` constructs a fallback result with `platforms: []`. In `search-symbols.ts`:
  ```ts
  filtered = filtered.filter(
  	(r) =>
  		r.platforms.length === 0 ||
  		r.platforms.some((p) => p.toLowerCase().includes(lowerPlat)),
  );
  ```
- **Observed Impact**:
  Because `r.platforms.length === 0` is interpreted as "matches all platforms", any pure semantic match bypasses the platform filter (e.g. an AppKit/macOS-only API can appear when `platform: "iOS"` is specified).
- **Remediation**:
  Look up the symbol's platforms from the `symbols` table by ID/path before returning, or populate `platforms` in `semantic_items`.
